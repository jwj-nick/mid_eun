## 멈춤 없는 병렬·대량 작업 프로토콜 (★ 실전 교훈 — 반드시 준수)

> 배경: 6인물 병렬 리서치를 **foreground Agent로 동시 발사 후 한꺼번에 await** 했다가, 1개가 멈추면(hang) 턴 전체가 수 시간 동결되고, 그동안 NCC는 그걸 **감지·중단할 수단이 없었다**(블로킹 대기 중엔 하트비트 불가). 게다가 압축 후 "발사된 적 없다"고 추론을 사실처럼 단정한 2차 오류까지 났다.

1. **블로킹 다중 await 금지.** 여러 foreground Agent를 한 번에 띄우고 전부 기다리지 않는다. 1개 hang = 전체 동결 = 복구 불가.
2. **병렬이 꼭 필요하면 background + 폴링.** `run_in_background`로 띄우고 `TaskList`/`TaskOutput`으로 진척을 직접 확인한다. 멈춤을 감지하면 중단·재시도.
3. **작은 배치 + 체크포인트.** 한 번에 6개보다 2개씩 3배치. 실패 비용을 '시간'이 아니라 '분'으로 묶는다. 배치마다 결과를 회수·검증 후 다음.
4. **경계가 분명한 리서치는 인라인 직접 진행이 가장 견고.** (예: N인물 조사·URL 검증) 매 스텝이 가시적으로 리턴되고, 멈추면 즉시 안다. 에이전트 반환 실패 리스크 0.
5. **상태는 추론이 아니라 실측으로 보고.** 산출물 부재는 "발사 안 됨"과 "발사 후 hang"을 구분하지 못한다. 시간 경과·로그·파일·`TaskList`를 확인하고, 모르면 "모른다 + 두 가능성"으로 보고한다. 추론을 사실로 단정 금지.

## 도구 결과 손실·인코딩·타임아웃 프로토콜 (★ 실측 교훈 — 반드시 준수)

> 배경: Windows(MINGW64/cp949) 환경에서 `[Tool result missing due to internal error]` / "내부 오류로 결과 없음"이 반복. **실측으로 잡은 근본원인 = cp949 콘솔이 한글·이모지 stdout에서 `UnicodeEncodeError`로 죽으면 툴 결과가 통째로 깨져 손실된다.** 추측 금지 — 아래는 재현·포착된 사실에 기반.

### A. 인코딩 (가장 흔한 원인 — 선제 예방)
1. **한글/이모지를 출력하는 모든 python·스크립트는 `PYTHONIOENCODING=utf-8`을 앞에 붙인다.** 예: `PYTHONIOENCODING=utf-8 python script.py`. 한 번이라도 빠지면 cp949에서 죽는다.
2. **콘솔로 한글을 길게 쏟지 않는다.** JSON·데이터 점검은 (a) utf-8 파일로 써서 Read 툴로 보거나, (b) ASCII 요약(키 존재여부·길이·bool)만 출력. 본문 확인은 Read 툴.
3. **heredoc(`<<'PY'`) 금지** — 아포스트로피·한글에서 파싱/인코딩 사고. **python은 `Write`로 임시파일 작성 → 실행 → `rm`.**
4. `print()` 대신 필요시 `sys.stdout.write(...)`로 개행·플러시 통제. 파일 입출력은 항상 `encoding="utf-8"` / `io.open(...,encoding="utf-8")`.

### B. 출력량·명령 형태 (손실·지연 예방)
5. **grep은 좁게** — 큰 HTML엔 `grep -o '패턴'`(매치부만)·`-c`(개수)·`| head`. raw 라인 전체를 뱉지 않는다.
6. **한 명령 = 한 목적.** 여러 무관한 출력을 한 번에 합치지 않는다(하나가 깨지면 전체 손실). 의존 없으면 별 호출.
7. 바이너리/대용량은 `file`·`ls -la`·크기로만 확인, 내용 덤프 금지.

### C. 결과가 없을 때 (추론 금지 · 즉시 재확인)
8. **`[Tool result missing]` / 빈 결과를 받으면, 명령이 됐는지 안 됐는지 추론하지 않는다.** 즉시 **최소 프로브**로 실제 상태를 측정한다(예: 방금 git commit이 의심되면 `git log --oneline -1`, 파일 생성이면 `ls -la`).
9. 재시도는 **원인을 고쳐서** 한다(인코딩 플래그 추가, 출력 축소). 똑같은 명령 무지성 반복 금지.
10. 부수효과 있는 명령(commit/push/배포 복사)이 결과없음으로 끝나면 **반드시 멱등 프로브로 적용 여부부터 확인** 후 다음 단계.

### D. 타임아웃·대기
11. 라이브/네트워크 대기는 **유한 루프 + 진행 출력 + 캐시버스트**(`?cb=$RANDOM`). 무한 `sleep` 금지. 종료조건은 새 자산의 실제 200(옛 콘텐츠 substring 매칭으로 false-pass 금지).
12. 긴 명령은 Bash `timeout` 파라미터를 의식적으로 설정. 멈출 위험이 크면 `run_in_background`+폴링([[멈춤 없는 병렬·대량 작업 프로토콜]]).

### E. 보고
13. 상태는 **실측만**. "됐을 것"·"안 됐을 것" 단정 금지. 모르면 "모른다 + 확인 명령"으로.
